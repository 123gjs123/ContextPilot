# Decisiones

| Fecha | Contexto | Decisión | Consecuencia |
| --- | --- | --- | --- |
| 2026-09-30 | La máquina no tiene VS Build Tools; módulos nativos no compilan | SQLite vía `sql.js` (WASM) detrás de un adaptador, no `better-sqlite3` | Persistencia por volcado a archivo; mismo esquema del SPEC |
| 2026-09-30 | El usuario no quiere API keys pagas | Traspaso (RF-HAN-01) usa la CLI de Claude Code en modo headless (`claude -p --model haiku`) con la suscripción; fallback: resumen extractivo local sin modelo | Sin costo extra; latencia de segundos |
| 2026-09-30 | Proxy TLS corporativo | Instalaciones con `NODE_OPTIONS=--use-system-ca`; runtime con `NODE_EXTRA_CA_CERTS` exportado del almacén de Windows | Script `scripts/with-ca.mjs` |
| 2026-09-30 | Transcripts de Claude Code repiten el mismo `message.id` en varias líneas con igual `usage` | Deduplicar por `message.id`; TTL de caché inferido de `cache_creation.ephemeral_1h/5m` | R2 usa TTL real |
| 2026-09-30 | Codex y Gemini CLI no instalados en la máquina | Parsers probados con fixtures sintéticos según formatos documentados; health «sin datos» hasta ver archivos reales | Verificación real pendiente |
| 2026-09-30 | Minimizar dependencias pesadas | Fastify reemplazable por `node:http` + `ws` si simplifica; embeddings R4 con un embedder local liviano (hashing n-gram TF) como default y `transformers.js` opcional | Sin descarga de modelos obligatoria |
| 2026-09-30 | Granularidad de `TurnEvent` no definida (un prompt de agente genera muchas llamadas a la API) | Un `TurnEvent` por llamada a la API (por `message.id` / respuesta); `turn` = índice del prompt de usuario, compartido por las llamadas de ese ciclo. Reglas que cuentan «turnos» (R6, W1, R3) cuentan valores distintos de `turn` | Acumulados exactos por llamada; umbrales de turnos no se inflan con tool loops |
| 2026-09-30 | Fórmula de ocupación de contexto | `contextSize` = `input + cacheRead + cacheWrite` de la última llamada (+ `output` de esa llamada para la próxima); `cacheRatio` = `cacheRead / (input + cacheRead + cacheWrite)` | R1, R2, statusline y badge usan la misma fórmula (core) |
| 2026-09-30 | Transcripts de subagentes en `<sesión>/subagents/*.jsonl` y líneas `isSidechain` | Se atribuyen a la sesión padre: suman a acumulados y a R5/R8, no modifican `contextSize` de la sesión principal | La statusline refleja el contexto real del hilo principal |
| 2026-09-30 | Ventana de contexto por modelo no está en el `usage` | Tabla en `packages/core` con defaults (Claude 200k; sufijo `[1m]` → 1M; Gemini 1 048 576; OpenAI según tabla) sobreescribible en config; modelo desconocido → 200k con `windowSource='default'` | Porcentajes pueden ser aproximados para modelos nuevos; se ve en la UI |
| 2026-09-30 | Estimador de tokens local (RF-NOR-03) sin nativos | `js-tiktoken` (`o200k_base`, JS puro) con factor de corrección por proveedor; calibración automática contra `output_tokens − thinking_tokens` de transcripts reales de Claude Code | ±15 % verificable para Anthropic; para Gemini web no hay verdad de terreno (se reporta como limitación) |
| 2026-09-30 | El traspaso necesita contenido pero RNF-01 prohíbe guardarlo por defecto | El contenido se lee en el momento del clic (transcript en disco o DOM de la página), se redacta y se procesa en memoria; nunca se persiste. El opt-in de contenido sólo habilita persistencia | RF-HAN-01 compatible con RNF-01; test de fuga en CP-006/CP-052 |
| 2026-09-30 | Quién escribe al portapapeles (RF-HAN-03) | Tray: `clipboard` de Electron; CLI sin tray: `scripts/handoff.mjs --copy` con PowerShell `Set-Clipboard`; extensión: `navigator.clipboard`. El daemon nunca toca el portapapeles | Sin dependencias nativas |
| 2026-09-30 | API local no cubre configuración, estadísticas ni OTLP | Se agregan `GET/PUT /config`, `GET /config/export`, `POST /config/import`, `GET /stats`, `POST /otlp/v1/logs` (OTLP/HTTP JSON, sin token, sólo loopback). `GET /health` y `/proxy/*` no exigen `X-CP-Token` (el proxy no puede agregar headers al SDK del usuario) | Superficie documentada; el resto exige token y valida `Origin` |
| 2026-09-30 | Distribución del token local a la extensión | Pegado manual en la página de opciones (una vez); sin native messaging (requiere registro y host ejecutable) | Un paso manual en la instalación |
| 2026-09-30 | Rutas de datos | `%LOCALAPPDATA%\ContextPilot\` para `token`, `config.json`, `cp.db`, `ca.pem`, logs. Retención de turnos 30 días | Una sola carpeta para backup/borrado |
| 2026-09-30 | R2 evaluado sólo en `UserPromptSubmit` llega tarde (el prompt ya salió) | R2 se evalúa además por temporizador al cruzar el TTL, para que la sugerencia esté visible antes de que el usuario vuelva a escribir | Aviso proactivo; una emisión por pausa |
| 2026-09-30 | Gemini CLI puede exportar OTLP por gRPC/protobuf (requiere dependencias pesadas) | Fuente primaria: `telemetry.outfile` (archivo local); secundaria: OTLP/HTTP JSON. gRPC y protobuf fuera de alcance | El instalador configura outfile por defecto |
| 2026-09-30 | Identidad de sesión en el proxy | Header opcional `X-CP-Session`; si falta, `sessionId` = hash(proveedor + hash del system prompt + hash del primer mensaje de usuario del body) | Conversaciones de SDK se agrupan sin guardar contenido |
| 2026-09-30 | Salida del proxy detrás del proxy corporativo | `undici` `EnvHttpProxyAgent` respetando `HTTPS_PROXY`/`NO_PROXY`; CAs vía `NODE_EXTRA_CA_CERTS` (`with-ca`) | Sin MITM propio (RNF-11) |
| 2026-09-30 | RNF-08 no puede cumplirse para el proxy (si el daemon cae, la base URL apunta a nada) | Excepción documentada: el usuario debe quitar la base URL; el tray muestra aviso si el proxy estuvo en uso y el daemon se reinicia | Limitación conocida, no bloqueante (fase 1, opt-in) |
| 2026-09-30 | R6 necesita definiciones de herramientas y los transcripts no las incluyen | R6 se evalúa con: proxy (array `tools` del body, exacto) y Claude Code (servidores MCP de la config + nombres de herramientas de los adjuntos del transcript), costo por turno marcado `≈` | En Codex/Gemini CLI R6 no se evalúa salvo vía proxy |
| 2026-09-30 | «Máx. una sugerencia visible por sesión» (RNF-13) sin criterio de desempate | Gana mayor severidad; empate → mayor ahorro estimado; el resto se agrupa en `detail`. Cooldown default 20 min por regla y sesión; «posponer» = 15 min | Determinista y testeable (CP-009) |
| 2026-09-30 | Algoritmo de RF-REG-04 | 3 `dismissed` seguidos de una regla → severidad −1 y cooldown ×2; un `accepted` resetea; en `info` + 3 descartes más → sólo side panel/dashboard. Nunca se deshabilita automáticamente | CP-014 |
| 2026-09-30 | Ahorro estimado sin método en el SPEC | Fórmula por regla en `packages/core/src/savings.ts`, horizonte fijo de 10 llamadas siguientes, tokens de `cacheRead` ponderados ×0,1; sólo cuenta como ahorro realizado con feedback `accepted`. Consumo propio del asesor (traspasos con modelo) se contabiliza aparte para RNF-14 | Cifras de ahorro son estimaciones marcadas `≈` |
| 2026-09-30 | Modo equipo (fase 3) no define transporte | Sin servidor: exportación local de agregados anonimizados a archivo JSON (buckets < 5 sesiones suprimidos, sin ids ni hashes) e importación de N archivos en el dashboard. `done` requiere aprobación de seguridad humana | Sin infraestructura nueva; se escala sólo la aprobación |
| 2026-09-30 | Adaptadores desktop (RF-CAP-09/10) dependen del spike | Sólo lectura CDP (`Network.*`); si el spike exige MITM, cambios de fuses o intervención de IT, se escala y la historia se cierra `won't` | Sin riesgo de seguridad sin aprobación |
| 2026-09-30 | Verificabilidad en esta máquina | Criterios marcados AUTO (vitest / `scripts/verify/*`) o MANUAL (sesión real de navegador, app desktop, juicio humano). Fixtures SSE/DOM web se graban una vez en sesión real y luego son AUTO. Contenido de fixtures de transcripts reales se reemplaza por placeholders antes de commitear | Tests reproducibles sin datos personales en el repo |
| 2026-09-30 | Estimador de tokens: la decisión de usar `js-tiktoken` agrega ~2 MB a la extensión | Se mantiene el estimador heurístico propio, recalibrado con `scripts/verify-estimator.ts` sobre 319 respuestas reales de Claude Code: error agregado +2,7 %, mediana −0,2 %, p10 −6,5 %, p90 +10,5 %, 89 % dentro de ±15 %. Reemplaza la fila de `js-tiktoken` | RF-NOR-03 verificado para Anthropic; OpenAI/Gemini sin verdad de terreno local |
| 2026-09-30 | Ruido de reglas medido con `scripts/replay-transcripts.ts` sobre 5 sesiones reales | R1 con histéresis por escalones de 10 puntos; ventana inferida a 1M cuando el contexto observado supera la nominal; R7 sólo con contexto < 30k (cambiar de modelo en sesión grande invalida la caché); R4 ignora prompts < 20 tokens | R1 bajó de 147 a 18 disparos en la sesión más larga |
| 2026-09-30 | CP-033/CP-034 dicen `input=input_tokens` / `input=input_token_count`, pero en OpenAI y Gemini ese valor incluye lo cacheado | Se aplica la convención de `types.ts` (`TokenUsage.input` = no cacheado): Codex/OpenAI `input = input_tokens − cached`, Gemini `input = promptTokenCount − cachedContentTokenCount` (+ `toolUsePromptTokenCount` en el proxy). `contextSize` = prompt total + output | Suma `input + cacheRead` = prompt informado (±0); comparable entre proveedores |
| 2026-09-30 | Codex repite `token_count` sin llamada nueva (y emite `info: null` sólo con rate limits) | Un `TurnEvent` por `token_count` con `info.last_token_usage`, deduplicado por `total_token_usage.total_tokens`; resultados de herramientas (`function_call_output`, `custom_tool_call_output`) se adjuntan a la llamada siguiente; fallo = `exit_code ≠ 0` / `Exit code: N` / `success:false` | R8 funciona con Codex; formato legado (sin `payload`) se lee sin uso |
| 2026-09-30 | Eventos de subagente (`sidechain`) en el motor | El motor sólo evalúa R5, R8 y R10 sobre eventos `sidechain`; `applyEvent` suma totales y `toolCalls` pero no toca `contextSize`, ventana, caché, modelo, `turns` ni `calls` | Sin falsos R1/R7 por el contexto o el modelo del subagente |
| 2026-09-30 | `windowSource` sin fuente «reportada» | `contextWindowInfo()`: override de config (`Config.contextWindows`, id exacto) → `table`; ventana informada por la fuente (Codex `model_context_window`) o inferida por contexto observado > nominal → `observed`; tabla → `table`; desconocido → `default`. Gemini = 1 048 576 | Campo opcional `windowSource` en `TurnEvent`, `SessionState` y `SessionView` |
| 2026-09-30 | Fórmulas de ahorro (D «ahorro») | `estimateSaving(ruleId, state, event?)` en `savings.ts`; el motor completa `estimatedSavingTokens` con esa fórmula (fallback: valor de la regla). R7, W4, R10 → 0 (el beneficio es precio/proyección, no tokens). Compactación conserva 25 %; traspaso ≈ 4k tokens | Desempate por ahorro usa la fórmula común |
| 2026-09-30 | Formato del export de equipo | Buckets por (semana ISO, proveedor) y (semana ISO, regla); `generatedAt` con precisión de día; `mergeTeamExports` suma buckets e informa `contributors` | Sin ids/hashes/rutas (test de fuga en `team.test.ts`) |
| 2026-09-30 | Ubicación de fixtures de core | Fixtures de parsers puros en `packages/core/test/fixtures/` (no en `fixtures/` raíz); `sanitizeTranscriptLine()` en core reemplaza todo string que no sea metadato por placeholder de igual longitud (conserva etiquetas `<tag>`), reutilizable por `scripts/verify/snapshot-fixtures.mjs` (CP-003) | El fixture Claude Code viene de un transcript real sanitizado |
| 2026-09-30 | Aceptación de fases 0–3 ([ACCEPTANCE.md](ACCEPTANCE.md)): desvíos menores entre implementación y criterios del backlog | Se aceptan (PO): mensaje WS `session` en lugar de `session-state` (API.md manda); W3 con acción `copy` (plantilla) en lugar de `show-detail` (mejor para RF-SUG-02); timeout de `hook.mjs` 1 s en lugar de 300 ms (con daemon caído sale en ~70 ms); selectores web en `src/sites.ts` en lugar de `selectors/gemini.ts`; informe de spike en `docs/SPIKE-desktop.md`; el backlog decía «17 reglas», el SPEC tiene 16. **No** se aceptan (quedan como defectos): R1 `info` bajo 80 % y sin foco, R10 por sesión tapando reglas de sesión, `Origin` sin id de extensión, R6 sin fuente de definiciones | Los criterios afectados por desvíos aceptados cuentan como PASS; el resto queda PARTIAL/FAIL en ACCEPTANCE §4 |
